This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Purpose

This repo is the **workload layer** of a personal homelab. It continues [`homelab-iac`](../homelab-iac/), which provisions the Proxmox guests (VMs/LXC). Everything here assumes the Docker VM already exists.

```
homelab-iac  →  homelab-deploys
(Proxmox: netuno + terra VMs, LXC)   (docker-compose stacks on netuno)
```

**Current scope = Phase 1 only.** Code for later phases (Postgres/Garage consolidation, user apps, media/cloud, Kubernetes + GitOps, observability) was intentionally removed and is re-implemented gradually, one phase at a time. Do not reintroduce it unless the user asks for that phase. The roadmap lives in the user's private notes, not in this repo.

All entry points go through `just`. Never run `ansible-playbook` directly unless debugging.

## Common Commands

```bash
just secrets-keygen    # Generate vault password at ~/.config/homelab-iac/.vault_pass
just secrets-edit      # Edit encrypted vault.yml (decrypt → edit → re-encrypt)
just init              # Install hooks + Galaxy collections + dependency check
just deploy-stacks     # Deploy all stacks (adguard → tailscale → duplicati)
just deploy-stacks adguard   # One stack (tags: adguard | tailscale | duplicati)
just secrets-view      # View decrypted vault.yml
just plugin off|on     # Disable/enable the aesthetic output plugin (use off when debugging)
just pr-review / pr-list     # Renovate PR triage
```

## Architecture

```
Justfile → src/main.yaml → role docker-stacks → SSH alias `docker` → /opt/stacks/<stack>/
```

- **`src/main.yaml`** — one `docker-stacks` role run per stack (vars `stack_name`), tags `docker-stacks` + the stack name. Order: adguard, tailscale, duplicati.
- **`src/hosts.yaml`** — `docker_hosts` group, host `docker` with `ansible_host: docker` (SSH alias generated by homelab-iac; user, IP and key come from `~/.ssh/servers/homelab.conf`, nothing hard-coded).
- **`src/group_vars/all/stacks.yml`** — source of truth: `docker_stacks` list (dirs, required vars, env, seed templates) + pinned image versions.
- **`src/group_vars/all/vault.yml`** — encrypted secrets (always encrypted in Git).
- **`src/roles/docker-stacks/`** — generic role: asserts required secrets, creates `/opt/stacks/<name>/` + data dirs, renders `compose.yaml` and `.env` (0600, `no_log`), renders seed configs only if missing (`force: false`), runs `community.docker.docker_compose_v2`.

### Stacks

| Stack | Notes |
|---|---|
| `adguard` | Host network, DNS on 53, UI on 3000. Seed `AdGuardHome.yaml` (admin + rewrites `*.<domain>` → gateway IP, `ha.<domain>` → `haos_ip`) is written once; afterwards the UI owns it. Needs systemd-resolved stub listener disabled (done by homelab-iac). |
| `tailscale` | Subnet Router `homelab-router` advertising `192.168.1.0/24`, tag `tag:homelab`. Needs IP forwarding (homelab-iac). |
| `duplicati` | UI on 8200; `/opt/stacks` mounted read-only as source. Does NOT take consistent DB dumps — run `pg_dump` into a folder it reads. |

### Ordering rule — DNS first

Deploy AdGuard **before** HAOS and Tailscale: HAOS (`ha.<domain>` rewrite) and the Tailscale split-DNS depend on it. Do not decommission any old DNS until the new one has run stable for a few days. Set `haos_ip` in `stacks.yml` once the HAOS VM IP is known.

### Manual steps (cannot be automated)

1. Router DHCP: DNS → netuno (keep a secondary DNS as contingency).
2. Tailscale admin console: approve the subnet route, disable key expiry for `homelab-router`, add split-DNS (custom nameserver = AdGuard IP, restricted to `frank.lab.io`), ACLs. Test from mobile data.
3. Duplicati UI: create the Google Drive job (AES-256; passphrase in the password manager), then run a real restore test.

## Ansible Conventions

- **Task names**: double quotes, English
- **Inventory format**: YAML only — `.ini` is prohibited
- **Module priority**: native modules over `shell`/`command`
- **Idempotency**: safe to re-run; seed configs never clobber a running service's config
- **`gather_facts`**: `false` by default
- Adding a stack: add an entry to `docker_stacks` (+ image version var), create `roles/docker-stacks/templates/<name>/compose.yaml.j2`, add a role run with tags `[docker-stacks, <name>]` to `src/main.yaml`, add the image to `renovate.json`, update this file and the README.

## Secrets Management

**This is a PUBLIC repository — never commit real secrets, tokens, hashes, passwords or credential hints.**

- `src/group_vars/all/vault.yml` is always encrypted in Git (pre-commit hook enforces it)
- Vault password: `~/.config/homelab-iac/.vault_pass` (`chmod 600`)
- Required keys: `vault_become_pass`, `vault_adguard_admin_password_hash` (bcrypt), `vault_tailscale_authkey`, `vault_duplicati_ui_password`, `vault_duplicati_settings_key`
- Edit with `just secrets-edit`. Programmatic edits: `just secrets-decrypt` → edit → `just secrets-encrypt` immediately.
- Auth keys/passphrases also belong in the password manager, never in Git.

## Renovate Maintenance

Whenever an image version variable is added or modified in `src/group_vars/all/stacks.yml`, add or update the matching `customManagers` entry in `renovate.json` (regex on `stacks.yml`, `datasourceTemplate: docker`, `depNameTemplate` = image name).

## Session Start — Renovate PR Triage

When the session starts and the context contains `RENOVATE_PRS_PENDING`, perform this triage automatically (no need to ask the user):

1. **Fetch full PR list** — run `just pr-list` (calls `scripts/pr-review.sh --list`), which outputs all open PRs with title, author, URL, and body in a readable format.
2. **Evaluate each PR** — A PR is safe to approve if it is a routine version bump (docker image tag, GitHub Action pinned SHA, dependency patch/minor) with no breaking-change notes in the body. Skip (do not approve) if the body mentions breaking changes, deprecations, or major version jumps that require config changes.
3. **Approve safe PRs** — `gh pr review <number> --approve --repo frankjuniorr/homelab-deploys`
4. **Sync local branch** — `git pull` after all PRs are handled
5. **Report** — Briefly list which PRs were approved and which were skipped (and why)

Use the `git-specialist` sub-agent (via `Agent` tool) for any `gh` operations if the triage is complex.

> **Standalone usage:** `just pr-review` launches the full interactive TUI (requires `gum`) where you can browse PRs, read their body, and approve or merge with keyboard navigation.

## Gotchas

- The **beautiful_output** callback plugin can hide error details — run `just plugin off` when debugging
- `beautiful_output.py` requires the `watchdog` Python library
- Pre-commit hook checks vault encryption; run `just install-hooks` after modifying `scripts/pre-commit.sh`
- Port 53 conflict on the VM = systemd-resolved stub listener still enabled (homelab-iac `docker-host` role should disable it)
