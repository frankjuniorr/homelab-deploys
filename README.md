The **workload layer** of a personal homelab. [`homelab-iac`](https://github.com/frankjuniorr/homelab-iac) provisions the Proxmox guests (including the Docker VM `netuno`); this repo deploys the services that run on it as **docker-compose stacks**, driven by Ansible.

## Phase 1 stacks (Docker VM `netuno`)

| Stack | Purpose |
| :--- | :--- |
| **AdGuard Home** | LAN DNS + ad blocking; rewrites `*.frank.lab.io` and `ha.frank.lab.io` |
| **Tailscale** | Subnet Router advertising the LAN — remote access without opening any router port (works behind CGNAT) |
| **Duplicati** | Encrypted, versioned off-site backups (Google Drive) of `/opt/stacks/*/data` and Home Assistant backups |

Home Assistant OS runs in its own VM (`terra`), provisioned by `homelab-iac` — it is not part of this repo.

> Roadmap (not implemented here yet): consolidate Postgres/Garage, user apps, media/cloud, Kubernetes + GitOps, observability. Each phase is added to this repo only when it is actually implemented.

## How to Use

### Prerequisites

- Docker VM `netuno` provisioned by `homelab-iac` (Docker Engine + compose plugin, `/opt/stacks`)
- SSH alias `docker` available (generated by `homelab-iac` in `~/.ssh/servers/homelab.conf`)
- `ansible`, `python3`/`pip3`; Python dependency `watchdog` (output plugin)

### First-time setup

```bash
just secrets-keygen   # Generate vault password at ~/.config/homelab-iac/.vault_pass
just secrets-edit     # Add the secrets listed below
just init             # Hooks + Galaxy collections (community.docker) + dependency check
```

### Deploy

```bash
just deploy-stacks             # adguard → tailscale → duplicati
just deploy-stacks adguard     # a single stack (tags: adguard | tailscale | duplicati)
```

> [!IMPORTANT]
> Order matters: deploy **AdGuard first** — Home Assistant (`ha.<domain>`) and the Tailscale split-DNS depend on it.

### Secrets (`src/group_vars/all/vault.yml`, Ansible Vault)

| Variable | Used by |
| :--- | :--- |
| `vault_become_pass` | sudo on the Docker VM |
| `vault_adguard_admin_password_hash` | AdGuard admin user (bcrypt hash) |
| `vault_tailscale_authkey` | Tailscale first login (reusable/expiring key from the admin console) |
| `vault_duplicati_ui_password` | Duplicati web UI |
| `vault_duplicati_settings_key` | Duplicati settings encryption key |

```bash
just secrets-edit     # Decrypt → edit → re-encrypt (recommended)
just secrets-view     # View decrypted vault in the terminal
just secrets-encrypt  # Encrypt before committing, if decrypted manually
```

### Manual steps after the first deploy

1. **AdGuard** — UI on `http://<netuno>:3000`; point the router DHCP DNS to netuno (keep a secondary DNS as contingency).
2. **Tailscale** — in the admin console: approve the `192.168.1.0/24` route, disable key expiry for node `homelab-router`, add split-DNS (custom nameserver = AdGuard IP, restricted to `frank.lab.io`), set ACLs; test from mobile data.
3. **Duplicati** — UI on `http://<netuno>:8200`; create the Google Drive job (AES-256, passphrase in the password manager), then run a **real restore test**.

## Project Structure

```
src/
├── main.yaml                 # Playbook: docker-stacks role, one run per stack
├── ansible.cfg               # Ansible config (beautiful_output callback)
├── hosts.yaml                # Inventory: localhost + docker_hosts (docker → netuno)
├── requirements.yml          # Galaxy collection: community.docker
├── group_vars/all/
│   ├── vars.yml              # Global vars (domain, become pass reference)
│   ├── stacks.yml            # Stack definitions + image versions (Renovate-tracked)
│   └── vault.yml             # Encrypted secrets (Ansible Vault)
└── roles/docker-stacks/      # Generic role: dirs, compose.yaml, .env, seed configs, compose up
    └── templates/<stack>/    # compose.yaml.j2 (+ seed config templates)
```

Host layout: `/opt/stacks/<stack>/{compose.yaml,.env,data/}` — one directory per stack, bind-mounts under `data/` so backup is trivial.
